# Ride Height Studio

The owner's 740d xDrive on OEM 21-inch wheels is already about 20 mm below factory height through its existing calibration. The owner's intended feature is temporary physical height control at the measured baseline, about +20 mm (factory), and about +40 mm (20 mm above factory), returning to the lowered baseline after restart. This version does **not** implement arbitrary millimetre targets.

Version 0.6.0 keeps all three VDP preset commands and adds direct pneumatic axle control through VDP's `STEUERN_DIGITALSIGNALE` (`DB77`) job. Front uses BMW's aggregate front-air-spring local ID `C6`; rear uses aggregate rear-air-spring ID `C3`. Vent is action `2`, compressor fill is action `3`, and every command carries a selectable 1–30 second ECU timer followed by an explicit action `0` OFF command. There is no action-count lockout. This does not write calibration or pretend that Low/Standard/High is manual pressure control.

The app requires fresh head-unit speed and gearbox signals showing a stationary car in Park. It independently reads VDP's filtered speed (`DD3A`) immediately before each write, reads VDP identity (`F150`), checks the height-sensor status (`DC06`), and reads the relative height sensors (`DC05`) before and after axle actuation. These sensor values are not rim-to-fender measurements. The physical measurements entered by the owner stay saved in `ride-height-plan.json`; the selected preview resets to zero on app restart.

The former 0.5.0 build targeted individual corner spring IDs (`C4`, `C5`, `C1`, `C2`) with fixed one-second commands. On this car VDP rejected those individual-corner requests with NRC `0x22`. Version 0.6.0 instead uses the aggregate axle IDs exposed by the same BMW VDP diagnostic definition. Axle acceptance still requires an in-car test; a positive package/unit test proves packet construction, not ECU acceptance.

**Calibration incident on 2026-11-03:** A direct ENET diagnostic probe sent `2E DC2C` in the VDP extended session. The VDP accepted the write and changed the front-left S1 calibration offset from its saved original `-21.081808 mm` to `-12.746038 mm`. Sending the original value back to `DC2C` was also accepted but did **not** restore S1. The other three S1 offsets remained unchanged. The original full `DC0B` response and raw bytes are backed up in `outputs/BMW/vdp-probes/vdp-offset-FL-20261103T162504656671Z.json`. No nonvolatile calibration-save routine (`4006`) was called, but persistence across VDP sleep has not yet been checked. The car was found to be on nonlevel ground; perform no further calibration writes until it is on level ground. The `Probe-VDP-Offset.py --execute` path is disabled. Do not describe the car as restored based solely on a positive UDS reply; verify `DC0B` readback. If the original value does not return after VDP sleep, use BMW ISTA's VDP ride-height adjustment procedure on level ground to restore the calibration.

The BMW diagnostic file `C:\EC-APPS\EDIABAS\ECU\VDP_G11.PRG` exposes no temporary arbitrary-millimetre setpoint. Version 0.6.0 therefore provides timed physical fill/vent control per axle and reports the relative sensor response; it does not claim a target height was reached.

Local checks: `python kit/tools/check_signals.py`, `python kit/tools/build.py ride_height`, and `node kit/tools/test_ride_height.js`. These verify catalog compatibility, fail-closed Park/speed gating, the exact aggregate-axle `DB77` packet layout, explicit OFF packets, and that individual-corner IDs cannot be written.
